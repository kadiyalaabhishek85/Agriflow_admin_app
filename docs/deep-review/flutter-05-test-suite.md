# Deep Review — Flutter Test Suite (leaf-1.1.5)

## Scope

This review covers every file under `test/` in the AgriFlow Admin & Manager Flutter application (16 files, enumerated below), as required by the gate ledger `.unlazy/deep-review/gates/leaf-1.1.5.md`. The work was performed read-only: I read all 16 test files end to end, then read the `lib/` production files each test imports (plus the remainder of `lib/` to establish what has no coverage), and I did not execute `flutter test`, `flutter analyze`, formatters, or any other mutating command.

Measured baseline recorded by the parent on this machine and quoted here as fact, not re-run by me: `flutter analyze --no-pub` => `No issues found!`; `flutter test` => `All tests passed!`. The suite is therefore green; this document is about what that green result does and does not prove.

Backend truth is `openapi_dump.json` at the repository root (94 paths). No endpoint, payload, table or business rule is invented anywhere in this report. Where a feature cannot be completed or tested because the backend contract does not exist, the report records: Backend API required - to be supplied by Syed.

The suite contains roughly 200 declared test cases across unit, controller, HTTP, widget and layout categories, and it covers six of the application's major features (auth, farmers, seed inventory, seed purchase, booking slots, farm visits, grain sales, both dashboards, and navigation) to very different depths — some features have five layers of tests, others have none.

## Test techniques used

**Pure unit tests** are used heavily and well: entity JSON parsing against snake_case backend shapes, pagination `hasMore` arithmetic, exception status-code tables, and `UserRole` mapping. This is the strongest layer of the suite and it exists for every feature (`farm_visit_test.dart:315-393`, `grain_sale_test.dart:189-316`, `seeds_inventory_test.dart:107-246`, `farmer_test.dart:193-309`).

**Controller/state tests** are the second pillar: every feature controller is exercised through hand-written fake repositories that record call arguments and can be told to throw (`_MockSeedPurchaseRepository` at seed_purchase_test.dart:87, `_MockFarmVisitRepository` at farm_visit_test.dart:175, `_MockBookingRepository` at booking_slot_test.dart:89). These assert initial state, loading→success, error transitions, refresh semantics, and append-vs-replace pagination semantics. Thorough, with the exception of `FarmerController`, whose pagination and detail paths are never called (see Findings).

**HTTP data-source tests** using `package:http/testing.dart` `MockClient` exist for exactly two of six remote data sources: `farmer_test.dart:312-480` and `seeds_inventory_test.dart:253-422`. They assert method, path, headers, request body and status→exception mapping — the best contract-level coverage in the repository. The other four features mock the data-source *interface* instead, so no wire format is verified for them.

**Widget tests** render real screens with a mocked controller, then tap real controls: confirmation dialogs (`seed_purchase_test.dart:544-613`), detail bottom-sheets (`farm_visit_test.dart:687-751`), form submission (`login_screen_test.dart:92`), and drawer navigation (`navigation_shell_test.dart:171-232`). Interaction coverage is good for the flows it touches.

**Layout/overflow assertions** (golden-*ish*, but not golden) appear in nine files: the viewport is resized and `tester.takeException()` is asserted null (`seeds_inventory_test.dart:788`, `manager_dashboard_test.dart:314`, `farm_visit_test.dart:778`). There are no `matchesGoldenFile` golden tests and no `integration_test/` suite anywhere in `test/`.

**Not used at all:** mocktail/mockito codegen (all fakes are hand-rolled — acceptable, arguably better), golden screenshots, integration tests, network-level 401→logout integration, and any test of scroll-driven pagination.

## Findings

1. **`widget_test.dart` tests a showcase screen that production never mounts.** `test/widget_test.dart:14` pumps `AgriFlowApp(showcaseMode: true)`, which routes to `FoundationShowcaseScreen` (`lib/app.dart:164`, selected at `lib/app.dart:40-42`). The production entry point never sets it (`lib/main.dart:20`). Consequently the test's headline assertions — `'MILESTONE 1 VERIFIED'`, `'MANAGER CONSOLE'`, role switching (test/widget_test.dart:19-35) — verify a Milestone-1 design-system showroom, not `AdminShell`/`ManagerShell` or `AuthRouter`. The real routing is covered elsewhere (`navigation_shell_test.dart:71-124`), so this test mostly locks in legacy showroom copy. It also advances four seconds past the toast timer (test/widget_test.dart:38) precisely so a toast *could* be observed, then never asserts the toast text that `lib/app.dart:185-188` should have shown.

2. **A test named for behaviour it does not check.** `test/widget_test.dart:41` is titled "StatusPill component resolves correct styles" but the only assertions are that three label strings exist (test/widget_test.dart:56-58). `StatusPill`'s `PillType.good/warn/bad` → colour/decoration mapping (`lib/core/widgets/status_pill.dart:43`) is never observed; the test would pass for a pill that rendered every state identically.

3. **Validation tests that never submit a form.** `test/features/seeds_inventory/seeds_inventory_test.dart:697` claims "validates input" but only asserts static labels (lines 726-733); it never taps `Save Changes`, so the real validators — name length, `Price must be greater than 0`, `Stock must be 0 or greater` (`lib/features/seeds_inventory/presentation/widgets/add_edit_seed_sheet.dart:97`, `:107`, `:114`) and `_handleSubmit` at `:122` — are unreachable from the suite. Likewise `test/features/grain_sales/grain_sale_test.dart:618` ("renders intake form fields and validates correctly") only asserts field labels (lines 643-650) and never presses `Save Procurement Entry`, leaving the quantity validator at `lib/features/grain_sales/presentation/widgets/log_received_crop_sheet.dart:400` and its `_handleSubmit` at `:102` untested. `test/features/farmers/farmer_test.dart:756` ("validates required fields") asserts only the name message (line 786); phone and password validators in `lib/features/farmers/presentation/widgets/add_farmer_sheet.dart` are never exercised.

4. **The farmers responsive test does not actually resize the viewport.** `_buildTestApp` (`test/features/farmers/farmer_test.dart:177-186`) injects a `MediaQueryData(size:)` wrapper, and the loop at `test/features/farmers/farmer_test.dart:856-879` never assigns `tester.view.physicalSize`. The test surface therefore stays at the default 800×600 logical size while the widget merely *believes* it is 320×600 — constraint-driven `RenderFlex` overflows at 320px cannot be detected. Contrast the correct pattern used elsewhere: `test/features/auth/responsive_test.dart:50-52` and `test/features/seeds_inventory/seeds_inventory_test.dart:768-770`.

5. **Error-handling test titles over-promise.** `test/features/seed_purchase/seed_purchase_test.dart:446` is titled "handles 401/403/404/5xx exceptions explicitly" but constructs exactly one 401 exception and asserts only its message (lines 448-454); `test/features/booking_slot/booking_slot_test.dart:476` is identical (lines 478-484). Both features can only ever test one class anyway: `lib/features/seed_purchase/domain/entities/seed_purchase_exception.dart:1` and `lib/features/booking_slot/domain/entities/booking_exception.dart:1` each define a single exception, whereas farm visits and grain sales define typed hierarchies that *are* asserted properly (`farm_visit_test.dart:385-392`, `grain_sale_test.dart:294-315`).

6. **Four of six remote data sources have no HTTP-level test.** `SeedPurchaseRemoteDataSourceImpl` (`lib/features/seed_purchase/data/datasources/seed_purchase_remote_data_source.dart:29`), `BookingRemoteDataSourceImpl` (`lib/features/booking_slot/data/datasources/booking_remote_data_source.dart:30`), `FarmVisitRemoteDataSourceImpl` (`lib/features/farm_visits/data/datasources/farm_visit_remote_data_source.dart:54`) and `FastApiGrainSaleRemoteDataSource` (`lib/features/grain_sales/data/datasources/grain_sale_remote_data_source.dart:43`) are replaced by interface mocks (`seed_purchase_test.dart:20`, `booking_slot_test.dart:21`, `farm_visit_test.dart:21`, `grain_sale_test.dart:19`). URL construction, query parameters, auth headers and response unwrapping for those features are verified nowhere.

7. **The entire auth data layer is untested**, including the session-expiry path. No test imports `FastApiAuthRemoteDataSource` (`lib/features/auth/data/datasources/auth_remote_data_source.dart:23`) or `AuthRepositoryImpl` (`lib/features/auth/data/repositories/auth_repository_impl.dart:9`). The refresh-on-401 branch at `lib/features/auth/data/repositories/auth_repository_impl.dart:77-80`, the refresh request itself (`lib/features/auth/data/datasources/auth_remote_data_source.dart:109`), and `AuthException.isUnauthorized` (`lib/features/auth/domain/entities/auth_exception.dart:16`) have zero coverage. Session expiry is asserted only as a *message* on feature controllers (`seed_purchase_test.dart:454`); no test proves that an expired session leads to logout or a redirect to login.

8. **The password-reset flow is entirely untested.** `ForgotPasswordScreen` (`lib/features/auth/presentation/screens/forgot_password_screen.dart:9`) has no test file and is never pumped. `requestPasswordResetOtp`/`resetPasswordWithOtp` exist only as no-op stubs inside fakes (`test/features/auth/auth_controller_test.dart:38-45`, and the same stubs in four other files).

9. **The bank change request approval flow is untested end to end.** `FarmerController.loadBankChangeRequests` (`lib/features/farmers/presentation/controllers/farmer_controller.dart:279`) and `reviewBankChangeRequest` (`:304`), plus `BankChangeRequestsSheet` (`lib/features/farmers/presentation/widgets/bank_change_requests_sheet.dart:8`), are never invoked — although the mock data source already implements both operations (`test/features/farmers/farmer_test.dart:150`, `:165`). This is a full approval flow (`openapi_dump.json` exposes `GET /api/v1/farmers/bank-change-requests` and its review counterpart) with a working mock sitting unused.

10. **Dashboard navigation wiring is never exercised.** `AdminDashboardView` contains 16 `onNavigate`/`onTabSelected` call sites (`lib/features/admin/dashboard/presentation/screens/admin_dashboard_view.dart:86` through `:486`), but both dashboard tests pass no-op callbacks (`test/features/admin/admin_dashboard_test.dart:250-251`, `test/features/manager/manager_dashboard_test.dart:196-197`) and only assert that Quick Action *labels* exist (`admin_dashboard_test.dart:320-330`). Tapping "Seed Purchase" on the dashboard and reaching the right tab is unproven.

11. **Infinite-scroll pagination is only tested by calling `loadMore*` directly.** The real trigger is a scroll listener in five screens (`lib/features/seed_purchase/presentation/screens/seed_purchase_screen.dart:49`, `lib/features/booking_slot/presentation/screens/booking_slot_screen.dart:49`, `lib/features/farm_visits/presentation/screens/farm_visit_screen.dart:57`, `lib/features/grain_sales/presentation/screens/grain_sale_screen.dart:50`, `lib/features/farmers/presentation/screens/farmer_screen.dart:57`), and no widget test ever scrolls a list. Worse, `FarmerController.loadMoreFarmers` (`lib/features/farmers/presentation/controllers/farmer_controller.dart:104`), `refreshFarmers` (`:99`) and `loadFarmerDetail` (`:147`) have no unit test either.

12. **Both dashboard data layers are mocked at the wrong seam.** `FastApiAdminDashboardRemoteDataSource` (`lib/features/admin/dashboard/data/datasources/admin_dashboard_remote_data_source.dart:14`) / `AdminDashboardRepositoryImpl` (`lib/features/admin/dashboard/data/repositories/admin_dashboard_repository_impl.dart:5`) and the manager equivalents (`…/manager_dashboard_remote_data_source.dart:13`, `…/manager_dashboard_repository_impl.dart:5`) are never tested; only the repository *interfaces* are faked (`admin_dashboard_test.dart:17`, `manager_dashboard_test.dart:17`). Given that these endpoints aggregate many backend fields, a `MockClient` test would be the cheapest guard against schema drift.

13. **Timing-coupled waits.** `setFilter`/`setSearch` fire `loadPurchases()` without awaiting it (`lib/features/seed_purchase/presentation/controllers/seed_purchase_controller.dart:145`, `:152`), and the tests paper over the race with `await Future.delayed(Duration.zero)` (`seed_purchase_test.dart:411`, `:421`; same pattern at `booking_slot_test.dart:421`, `:452`) or a fixed 50 ms (`grain_sale_test.dart:485`). Any future debounce timer would silently make these assertions racy.

14. **Fire-and-forget async assertions.** `test/features/seeds_inventory/seeds_inventory_test.dart:387` declares `void checkError(int status, Type expectedType) async` and calls it five times without awaiting; each `expect(..., throwsA(...))` uses package:matcher's `AsyncMatcher`, so the test relies on the harness's pending-work tracking rather than explicit `await expectLater(...)`. Correct today, fragile tomorrow.

15. **No regression tests keyed to fixed defects.** The repository contains no bug log or changelog (`docs/milestones/*` records verification passes only, e.g. `docs/milestones/m5-step6-seeds-inventory-verification-report.md:158` "226 / 226 tests passed"). The one documented product risk — non-persisting inputs causing "silent data loss, and contract regression" (`docs/milestones/m5-seed-inventory-feature-parity-audit.md:373`) — is guarded by no test that submits the sheet (see Finding 3).

- *Backend-blocked behaviour:* seed grade pricing (A/B/C) and warehouse assignment fields cannot be given contract tests because `openapi_dump.json` exposes only the base `price_per_kg` schema — Backend API required - to be supplied by Syed. Likewise warehouse master-data edit/delete has no OpenAPI operation — Backend API required - to be supplied by Syed.

## Recommendations

1. **P0 — Retarget or delete the showcase residue in `widget_test.dart`.** Replace `AgriFlowApp(showcaseMode: true)` (`test/widget_test.dart:14`) with the production `AgriFlowApp(authController: …)` path (as `navigation_shell_test.dart:80` already does), and assert the toast that `lib/app.dart:185-188` fires after a role switch instead of only pumping past it (`test/widget_test.dart:38`).
2. **P0 — Make the three "validates" tests actually validate.** Tap `Save Changes` in `test/features/seeds_inventory/seeds_inventory_test.dart:697` and assert `lib/features/seeds_inventory/presentation/widgets/add_edit_seed_sheet.dart:97`/`:107`/`:114`; tap `Save Procurement Entry` in `test/features/grain_sales/grain_sale_test.dart:618` against `lib/features/grain_sales/presentation/widgets/log_received_crop_sheet.dart:400`; add phone/password assertions in `test/features/farmers/farmer_test.dart:756`.
