# Deep review: authentication, admin/manager shells and dashboards (leaf 1.1.2)

## Scope

This review covers every file under `lib/features/auth/**`, `lib/features/admin/**`, `lib/features/manager/**` and `lib/features/dashboard/**`, including all `.gitkeep` markers and everything beneath `dashboard/shared/`. Thirty-nine files match those globs and all thirty-nine are cited individually under `## Files reviewed`. Supporting files outside the leaf (`lib/main.dart`, `lib/app.dart`, `lib/core/models/user_role.dart`, `lib/core/navigation/nav_destination.dart`, `lib/core/widgets/custom_drawer.dart`, the HTML UI/UX references and `openapi_dump.json`) are cited inline where they explain behaviour owned by the in-scope code, but they are not part of the coverage list.

Ground truth is the local OpenAPI cache `openapi_dump.json` (94 paths). No endpoint, payload or business rule has been invented in this document: every endpoint named below was verified against that file, and every schema claim was read out of `components.schemas`. Response envelopes were re-verified for this revision: all sixteen `PaginatedResponse_*` schemas declare `properties.data.type == "array"` with `required: ["data","pagination"]`, and only `SuccessResponse_dict_` carries an object-typed `data`; the live contract at `https://agriflow-backend-t8o4.onrender.com/api/v1/openapi.json` returns the same 94 paths and the same array-typed `data`. Where the product needs backend capability that the contract does not provide, the literal sentence used is: Backend API required - to be supplied by Syed.

Method: static read-only analysis of each file with line-accurate citation, cross-checked against the OpenAPI schema for request fields, response envelopes, query parameters and enum values. No build, formatter, package manager or test runner was executed, and no file other than this report was created or modified.

## Authentication flow

**Wiring.** `lib/main.dart:11-20` builds `SharedPreferencesAuthLocalDataSource`, `FastApiAuthRemoteDataSource` and `AuthRepositoryImpl`, wraps them in `AuthController`, and injects the controller into `AgriFlowApp`. If no controller is injected, `lib/app.dart:62-65` substitutes `_UnconfiguredAuthRepository`, whose `restoreSession` always returns null (`lib/app.dart:123`) and whose `login` throws, so an un-wired build silently parks on the login screen for ever. `UnimplementedError` is thrown only inside that fallback — at `lib/app.dart:119` and `lib/app.dart:140` — and the same marker sentence is repeated only as documentation comments in `lib/core/network/api_contracts.dart`; no in-scope screen, controller or data source throws it, so the real stack is fully implemented.

**Remote contract.** `lib/features/auth/data/datasources/auth_remote_data_source.dart:57-62` posts `{phone, password}` to `/api/v1/auth/login`, matching `LoginRequest` exactly. The response envelope is `SuccessResponse[TokenResponse]`, i.e. `{success, data, message}`; the data source unwraps with `json['data'] ?? json` at `auth_remote_data_source.dart:67`, which tolerates both the wrapped and bare shapes. `AuthSession.fromJson` (`lib/features/auth/domain/entities/auth_session.dart:22-34`) reads `access_token`, `refresh_token`, `token_type`, `expires_in` and `user`, which is precisely the `TokenResponse` property set. `AuthUser.fromJson` (`lib/features/auth/domain/entities/auth_user.dart:25-38`) mirrors `UserPublic` (`id`, `name`, `phone`, `email`, `role`, `status`, `first_login`, `created_at`). Refresh posts `{refresh_token}` to `/auth/refresh` (`auth_remote_data_source.dart:115`), matching `RefreshRequest`.

**Storage.** `lib/features/auth/data/datasources/auth_local_data_source.dart:30-35` writes the access token, the refresh token, the serialised session and the `remember_me` flag into four SharedPreferences keys (`agriflow_access_token`, `agriflow_refresh_token`, `agriflow_session_json`, `agriflow_remember_me`). Tokens are stored in plaintext — SharedPreferences is an unencrypted store, and no `flutter_secure_storage` usage exists anywhere under `lib/features`. A corrupt session blob self-heals by clearing storage (`auth_local_data_source.dart:44-47`).

**Login and role gate.** `AuthRepositoryImpl.login` (`lib/features/auth/data/repositories/auth_repository_impl.dart:19-49`) authenticates, then enforces `session.role.isSupported` before persisting anything; an unsupported role clears storage and throws `AuthException(statusCode: 403, errorCode: 'UNSUPPORTED_ROLE')` (`auth_repository_impl.dart:31-39`). `AuthController.login` maps that code to `AuthState.unsupportedRole('Unauthorized')` (`lib/features/auth/presentation/controllers/auth_controller.dart:76-77`), every other exception to `authenticationFailure(message)` (`auth_controller.dart:79`), and success to `authenticated(session)` (`auth_controller.dart:73`).

**Role mapping.** `lib/core/models/user_role.dart:12-25` normalises the backend string: `super_admin`/`superadmin` → `superAdmin`, `admin`/`administrator` → `admin`, `manager` → `manager`, anything else → `unsupported`. The live contract's `UserRole` enum is only `farmer | manager | super_admin` (`openapi_dump.json`), so a real `admin` value never arrives today and `farmer` always lands on `unsupported`. `isSupported` accepts admin, superAdmin and manager (`user_role.dart:28-31`); `AuthController.currentRole` returns null for anything unsupported rather than defaulting to manager (`auth_controller.dart:19-23`).

**Restore, refresh and 401.** `AuthRepositoryImpl.restoreSession` (`auth_repository_impl.dart:52-109`) reads the cache, re-validates the role, calls `GET /users/me`, and on `401` with a non-empty refresh token calls `POST /auth/refresh` (`auth_repository_impl.dart:77-81`), re-checking the role of the refreshed session (`auth_repository_impl.dart:83-86`) before saving. A network error keeps the cached session (`auth_repository_impl.dart:98-100`); any other failure clears it (`auth_repository_impl.dart:103`). This is the **only** place in the whole repository that refreshes a token — once the user is inside a shell, no code path handles 401.

**Screens.** `SplashScreen` deliberately does not auto-restore: `initState` is empty (`lib/features/auth/presentation/screens/splash_screen.dart:24-29`) and `restoreSession` fires only on tap (`splash_screen.dart:31-37`), showing a spinner while `isSessionRestoring`. `LoginScreen` validates a 10-digit phone and a minimum-6-character password (`login_screen.dart:36-55`), drives `AuthController.login` at `login_screen.dart:67-71`, renders `state.errorMessage` in a red banner (`login_screen.dart:166-196`) and offers a remember-me checkbox (`login_screen.dart:325`). `ForgotPasswordScreen` is a two-step OTP flow: send (`forgot_password_screen.dart:49-83` → `POST /auth/forgot-password/send-otp`) then reset with `{phone, code, new_password}` (`forgot_password_screen.dart:104-118` → `POST /auth/forgot-password/reset`), with a helpline card and local 8-character password rule (`forgot_password_screen.dart:94`). On an unsupported role, `AuthRouter` shows `UnsupportedRoleScreen` (`lib/app.dart:79-84`), whose only action is `authController.logout()` (`unsupported_role_screen.dart:68`), which always lands in `unauthenticated` via `try/finally` (`auth_controller.dart:93-100`).

## Shells and navigation

Both shells are `StatefulWidget`s holding a route string and a tab index where `-1` means "on the dashboard, no bottom tab selected" (`lib/features/admin/presentation/admin_shell.dart:72-73`, `lib/features/manager/presentation/manager_shell.dart:73-74`). Each `initState` constructs seven controllers — dashboard, seed purchase, booking, farm visits, grain sales, farmers, seeds inventory — when they are not injected, all bound to the session's `accessToken` captured at construction (`admin_shell.dart:85-140`, `manager_shell.dart:86-141`), and `dispose` only disposes the ones it owns (`admin_shell.dart:178-202`, `manager_shell.dart:194-218`). Both wrap `AppScaffold` in a `PopScope` that returns to home instead of exiting (`admin_shell.dart:209-215`, `manager_shell.dart:225-231`), and both render `DrawerHeader`-driven navigation through `CustomDrawer`.

Tab indices come from `NavDestination` (`lib/core/navigation/nav_destination.dart`): admin uses four tabs — `seedPurchase` 0, `bookingSlot` 1, `farmVisits` 2, `grainSales` 3 (`nav_destination.dart:38-72`) — while manager adds a fifth, `account` with `managerTabIndex: 4` (`nav_destination.dart:158-164`). The admin shell's `_onTabSelected` handles only cases 0-3 (`admin_shell.dart:143-161`); the manager shell additionally maps index 4 to `account` (`manager_shell.dart:160-162`).

Implemented destinations vs placeholders: `home` renders `AdminDashboardView`/`ManagerDashboardView` (`admin_shell.dart:233-240`, `manager_shell.dart:249-256`); `seed-purchase`, `seeds-inventory` (with `isAdmin: true` for admin, `false` for manager), `booking-slot`, `farm-visits`, `grain-sales` (with `isManagerRole` false/true) and `all-farmers` (again `isManagerRole` false/true) are real screens (`admin_shell.dart:242-285`, `manager_shell.dart:258-301`). Everything else — `warehouse`, `billing`, `market-rates`, `reports`, `event-logs`, `managers`, `credits`, `cache-management`, `notifications`, `account`, `settings`, `help` — falls through to `ModulePlaceholderScreen` (`admin_shell.dart:287-294`, `manager_shell.dart:303-310`). That means twelve of the nineteen destinations are placeholders for both roles, including the manager's fifth bottom tab.

Drawer items are role-filtered in `lib/core/widgets/custom_drawer.dart:157-186`: admin sees Operations plus reports/event-logs and an Administration block (managers, all-farmers, credits, cache); manager sees all-farmers in Operations, plus notifications, account, settings and help; both roles also see Dashboard, account and settings (`custom_drawer.dart:176-186`). The manager shell adds a defense-in-depth guard: `_onNavigate` refuses any `destination.adminOnly` id with an "Access Denied" snackbar (`manager_shell.dart:167-178`), while `_onTabSelected` and `_buildCurrentScreen` apply no such guard (`manager_shell.dart:144-165`, `manager_shell.dart:248-311`).

The admin dashboard feature is a full clean-architecture slice: `FastApiAdminDashboardRemoteDataSource.fetchDashboardData` (`lib/features/admin/dashboard/data/datasources/admin_dashboard_remote_data_source.dart:42-185`) calls `GET /admin/dashboard` for KPIs, `GET /public/market-rates` for the mandi strip, six sequential `GET /admin/reports/monthly?month=YYYY-MM` calls for the trend chart, `GET /farm-visits` for total visits, `GET /warehouses` for the warehouse count and `GET /admin/audit-logs?page=1&page_size=5` for recent activity. `AdminDashboardData.fromJson` (`lib/features/admin/dashboard/domain/entities/admin_dashboard_data.dart:82-124`) maps the fifteen `AdminDashboardResponse` fields plus `MonthlyChartPoint`, `MandiRateItem` and `AdminAuditItem` lists. `AdminDashboardController` (`admin_dashboard_controller.dart:19-68`) drives `DashboardState` through loading/success/error/refreshing with `previousData` retention on refresh failure. The view (`admin_dashboard_view.dart:36-46`) shows `DashboardLoadingView` while loading, `DashboardErrorView` with retry when there is no data, otherwise a `RefreshIndicator` with a summary strip, a 2x2 operational grid, a system-overview grid, `DashboardChartCard`, quick actions, a ten-tile More Tools grid, `DashboardMandiStrip` and the audit list.

The manager dashboard mirrors that stack (`manager_dashboard_remote_data_source.dart:41-185`) but composes it from `GET /seed-purchases`, `GET /bookings`, `GET /farm-visits`, `GET /grain-sales`, `GET /admin/dashboard`, `GET /public/market-rates` and `GET /notifications`. `ManagerDashboardData` (`lib/features/manager/dashboard/domain/entities/manager_dashboard_data.dart:42-79`) holds nine scalars plus `mandiRates` and `recentNotifications`. Its controller is structurally identical to the admin one (`manager_dashboard_controller.dart:19-68`), and its view renders loading/error the same way (`manager_dashboard_view.dart:34-44`) before showing a summary strip, a 2x2 grid, quick actions, a four-tile operational-tools grid, the mandi strip and notifications.

The shared widgets are reused as follows. `DashboardSummaryStrip` (`lib/features/dashboard/shared/presentation/widgets/dashboard_summary_strip.dart:23-103`) renders the navy gradient hero with an amount, label and secondary line — used by admin at `admin_dashboard_view.dart:81-87` and manager at `manager_dashboard_view.dart:62-68`. `DashboardMetricCard` (`dashboard_metric_card.dart:29-99`) is the icon/value/label/delta tile used for all eight admin grid tiles and all four manager tiles. `DashboardChartCard` (`dashboard_chart_card.dart:31-101`) paints the custom Bezier area chart with an empty-text branch, and also owns the `MonthlyChartPoint` DTO consumed by the admin entity (`admin_dashboard_data.dart:55`). `DashboardMandiStrip` (`dashboard_mandi_strip.dart:44-147`) owns `MandiRateItem` and renders a horizontal card list, collapsing to `SizedBox.shrink()` when empty; both dashboards reuse it and both data sources import it for parsing. `DashboardStateViews` provides `DashboardLoadingView`, `DashboardErrorView` and `DashboardEmptyView` (`dashboard_state_views.dart:6,110,179`), shared by both dashboards — although `DashboardEmptyView` is only ever used by the grain-sales screen. `DashboardState` (`dashboard_state.dart:13-66`) is the generic status container used by both controllers.

## Findings

1. **"Today" figures are all-time totals, first-page counts or hardcoded constants.** `/seed-purchases`, `/bookings`, `/grain-sales` and `/farm-visits` expose only `page`, `page_size`, `search`, `status`, `sort`, `order` — no date filter (`openapi_dump.json`). The manager data source therefore assigns `bookingsToday = pagination.total` (`manager_dashboard_remote_data_source.dart:77-78`) and `grainSalesToday = pagination.total` (`manager_dashboard_remote_data_source.dart:105-106`), which are all-time totals; `todaySeeds = min(items.length, 5)` (`manager_dashboard_remote_data_source.dart:66`) and `farmVisitsToday = items.length` with `farmVisitsInProgress` counted from the same first page (`manager_dashboard_remote_data_source.dart:92-94`), which are first-page counts; `slotsRemaining = 10` (`manager_dashboard_remote_data_source.dart:46`) and `salesDelta = 1` (`manager_dashboard_remote_data_source.dart:110`), which are constants. When `GET /admin/dashboard` returns 200 for the manager (finding 3), `active_bookings`, `pending_grain_sales` and `visits_today` silently overwrite three of those values (`manager_dashboard_remote_data_source.dart:122-124`). The view then prints them as "new today", "slots left" and "vs yesterday" (`manager_dashboard_view.dart:168,178,198`) and repeats `todaySeedOrders`, `bookingsToday` and `farmVisitsToday` in the summary subtitle (`manager_dashboard_view.dart:66`). The HTML reference computes each of these from today's records (`Manager Dashboard UIUX.html:2695-2715`). Server-side date-filtered aggregates are required. Backend API required - to be supplied by Syed.

2. **Session expiry after login is unhandled.** Token refresh exists only inside `restoreSession` (`auth_repository_impl.dart:77-95`). Both shells freeze the access token at construction (`admin_shell.dart:90`, `manager_shell.dart:91`) and hand it to every controller; when it expires, each dashboard surfaces the 401 as a generic `DashboardErrorView` with a Try Again button (`admin_dashboard_controller.dart:26-35`, `manager_dashboard_controller.dart:26-35`, `dashboard_state_views.dart:158-161`) and retry can never succeed. `AuthStatus.sessionExpired` and `AuthState.sessionExpired()` exist (`auth_state.dart:11`, `auth_state.dart:53`) but are never constructed anywhere in the tree — dead states. There is no shared HTTP layer, so each of the three data sources reimplements headers and error parsing (`auth_remote_data_source.dart:38-47`, `admin_dashboard_remote_data_source.dart:35-39`, `manager_dashboard_remote_data_source.dart:34-38`).

3. **The manager dashboard reads an admin-scoped endpoint and mislabels its value.** `GET /admin/dashboard` is called from the manager feature (`manager_dashboard_remote_data_source.dart:116-118`) and any non-200 is swallowed (`manager_dashboard_remote_data_source.dart:119`), so under RBAC rejection `todayRevenue` silently stays `0.0`. The value taken is `revenue_mtd` (`manager_dashboard_remote_data_source.dart:125`) yet the UI labels it "Today's Revenue" (`manager_dashboard_view.dart:63-64`), and the reference design derives it from today's seed plus grain sales (`Manager Dashboard UIUX.html:2701-2707`). Month-to-date revenue presented as today's revenue is a factual UI error.

4. **Remember-me has no effect on restore, and tokens are plaintext.** Both branches of `AuthRepositoryImpl.login` call `saveSession` (`auth_repository_impl.dart:42-46`), and `restoreSession` never consults `isRemembered()` — it restores whatever is cached (`auth_repository_impl.dart:52-54`). `isRemembered()` is only read after a refresh (`auth_repository_impl.dart:88`). The checkbox in `login_screen.dart:325-338` therefore cannot stop the session persisting on the device, and `auth_local_data_source.dart:31-33` stores bearer and refresh tokens unencrypted in SharedPreferences.

5. **Admin and manager logic is duplicated nearly line for line.** The two controllers differ only in their type parameters (`admin_dashboard_controller.dart:19-68` vs `manager_dashboard_controller.dart:19-68`); the two repository impls are identical boilerplate (`admin_dashboard_repository_impl.dart:11-13` vs `manager_dashboard_repository_impl.dart:11-13`); the shells duplicate roughly 140 lines of controller construction, tab routing and disposal (`admin_shell.dart:82-202` vs `manager_shell.dart:83-218`); `_buildActionTile` is copy-pasted (`admin_dashboard_view.dart:364-413` vs `manager_dashboard_view.dart:298-347`); and base URL, headers, URI building and error parsing are triplicated across the auth, admin and manager data sources.

6. **Admin summary strip labels revenue as procurement.** `primaryAmount` is `data.revenueMtd` while `primaryLabel` reads "MTD Procurement" (`admin_dashboard_view.dart:82-84`), even though `procurementMtdKg` is available (`admin_dashboard_data.dart:46`). The reference shows today's revenue for the same slot (`AdminMobile UIUX.html:1930`). Its `onTap` routes to Booking Slot (`admin_dashboard_view.dart:86`), which is unrelated to the figure shown.

7. **Empty states are unreachable on both dashboards.** `DashboardState.empty()` is never produced by either controller, and `DashboardEmptyView` is never used by either dashboard view (only `lib/features/grain_sales/presentation/screens/grain_sale_screen.dart:263` uses it). Sections hide themselves instead: `DashboardMandiStrip` returns `SizedBox.shrink()` when rates are empty (`dashboard_mandi_strip.dart:45-47`), as do recent activity (`admin_dashboard_view.dart:465`) and notifications (`manager_dashboard_view.dart:350`). A dashboard whose collections are genuinely empty therefore renders as a successful page with silently missing sections and no explanation.

8. **Unsupported-role messaging degrades to a literal placeholder.** Because the repository throws before persisting a session (`auth_repository_impl.dart:31-39`), the controller has no role name to pass and hardcodes `'Unauthorized'` (`auth_controller.dart:76-77`), producing "Your account role (Unauthorized) is not authorized..." (`unsupported_role_screen.dart:60`). The branch that would carry the real role (`auth_controller.dart:41-42`) is unreachable: `restoreSession` returns null for an unsupported cached session first (`auth_repository_impl.dart:57-60`).

9. **Role checks are client-side, partial and asymmetric.** Only `ManagerShell._onNavigate` enforces `adminOnly` (`manager_shell.dart:168-178`); `_onTabSelected` (`manager_shell.dart:144-165`) and `_buildCurrentScreen` (`manager_shell.dart:248-311`) do not, and `AdminShell._onNavigate` has no guard at all (`admin_shell.dart:163-169`). Neither shell validates the role of the `AuthSession` it is handed (`admin_shell.dart:54-65`, `manager_shell.dart:55-66`), and `AuthenticatedAppShell` — which is never instantiated anywhere in the tree — routes any non-admin role, including `UserRole.unsupported`, to `ManagerShell` (`lib/app.dart:156-160`). Backend RBAC remains the only real barrier.

10. **The admin dashboard serialises six report requests on first paint.** `/admin/reports/monthly` requires a `month` parameter (`openapi_dump.json`), so the chart loop issues six sequential GETs with a 5-second timeout each (`admin_dashboard_remote_data_source.dart:85-105`) inside a single fetch, adding up to ~30 seconds against a cold backend before the dashboard resolves. Failure of any month is silently skipped, and the fallback emits one point labelled "MTD" (`admin_dashboard_remote_data_source.dart:111-116`).

11. **Smaller contract and polish issues.** `AdminAuditItem.userName` can never be populated because `AuditLogPublic` has no `user_name` or `user` field (`admin_dashboard_data.dart:32`, `openapi_dump.json`), and the view never renders it. `first_login` is parsed but never acted on (`auth_user.dart:11,33`), so a forced password change never happens even though `POST /auth/change-password` exists in the contract and no screen in scope calls it. Both shells hardcode `unreadNotifications: 0` and `pendingOrders: 0` (`admin_shell.dart:225-226`, `manager_shell.dart:241-242`) so drawer badges can never appear, even though the manager dashboard already fetches notifications. Both shells fall back to the literal names `'Super Admin'` and `'Manager Account'` (`admin_shell.dart:223`, `manager_shell.dart:239`). `NavDestination.fromId` silently maps unknown ids to `home` (`nav_destination.dart:202-207`), hiding routing typos behind a dashboard render.

12. **Positive verification: routes and response envelopes match the contract.** No in-scope code calls an endpoint that is absent from `openapi_dump.json`. Auth uses `/auth/login`, `/auth/refresh`, `/auth/logout`, `/users/me`, `/auth/forgot-password/send-otp`, `/auth/forgot-password/reset`; the admin dashboard uses `/admin/dashboard`, `/public/market-rates`, `/admin/reports/monthly`, `/farm-visits`, `/warehouses`, `/admin/audit-logs`; the manager dashboard uses `/seed-purchases`, `/bookings`, `/farm-visits`, `/grain-sales`, `/admin/dashboard`, `/public/market-rates`, `/notifications`. Those are 16 distinct paths, every one present in the 94-path cache. Envelopes are equally sound: all sixteen `PaginatedResponse_*` schemas — including `PaginatedResponse_AuditLogPublic_`, which is what `GET /admin/audit-logs` 200 returns — declare `data` as an array (the live `openapi.json` reproduces this), so the `json['data'] is List` parses at `admin_dashboard_remote_data_source.dart:159` and `manager_dashboard_remote_data_source.dart:60`, `:92`, `:154` read those bodies correctly, and Recent Activity, Recent Notifications, `todaySeedOrders` and `farmVisitsInProgress` are populated whenever the backend returns rows. The real defects are semantics, labelling and session lifecycle, not invented routes or a wrong envelope.

## Recommendations

**P0 — correctness of data on screen.**

1. Stop presenting all-time totals and constants as "today": replace `manager_dashboard_remote_data_source.dart:46`, `:66`, `:77-78`, `:92-94`, `:105-106`, `:110` and `:125` with real date-scoped aggregates. Until the contract supports it: Backend API required - to be supplied by Syed. Meanwhile compute slot availability from the documented `GET /warehouse-slots?date=YYYY-MM-DD` using `capacity_kg - booked_kg` (both fields are present on the `WarehouseSlotPublic` items that endpoint returns) instead of the literal `10`, and relabel unfilterable counters as totals rather than "today".
2. Fix the admin summary label at `admin_dashboard_view.dart:82-84`: either bind the amount to `procurementMtdKg` or rename the label to MTD revenue, and point `onTap` at a revenue-relevant destination instead of `onTabSelected(1)`.

**P1 — session lifecycle and role safety.**

3.
